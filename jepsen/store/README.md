# Jepsen histories

A linearizability verdict is only evidence if the history behind it can be
re-checked. This directory holds the recorded runs.

## Layout

```
store/<test-name>/<timestamp>/
    results.edn     the checker verdict
    history.txt     the operation history the verdict was computed from
    jepsen.log      the run log
```

## What is here

- Runs produced by `scripts/jepsen-local-gate.sh` are ignored by git, so a local
  run does not dirty the tree. CI keeps its run as a build artifact
  (`jepsen-store`) on every push, and prints the verdict as a run annotation.
- The **networked Sentinel run** quoted in `EVIDENCE.md` is the authority for
  behaviour under TC network faults and is checked in under its own timestamp
  directory. It cannot be regenerated by CI, which has no namespaces to
  partition, so its raw history belongs in the repository rather than in an
  expiring artifact.

## Re-checking a history

```bash
cd jepsen
lein run test --time-limit 20 --concurrency 5   # produce a fresh run
```

The gate script asserts `:valid? true` and exits non-zero otherwise; do not read
a run as passing without that check.
